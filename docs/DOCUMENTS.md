# TRORECRUITER — Документи

## Підтверджений потік
1. Користувач відкриває документи конкретного кандидата.
2. CRM читає `documents` за `candidate_id`.
3. CRM читає активні `document_requirements`.
4. Файл завантажується у Supabase Storage bucket `candidate-documents`.
5. Шлях нового файла формується як `<candidate_id>/incoming/<unique_filename>`.
6. Документ може класифікуватися через Edge Function `ai-classify-document`.
7. У списку документів статус визначається через `verification_status` та `processing_status`.

## Статуси, які вже підтримує UI
- якщо немає документа: `Не завантажено` / `Не додано`;
- після завантаження: `Завантажено · перевірити`;
- після AI: `AI розпізнано · перевірити`;
- після підтвердження: `Підтверджено`.

## Рекомендаційний лист
Тип документа `Рекомендаційний лист` має бути окремим типом у довіднику/реєстрі та бути прив'язаний до кандидата.

## Правильний життєвий цикл
`Завантажений → Розпізнаний → Перевірений/Підтверджений`

OCR/AI не повинен автоматично робити документ перевіреним. Перевірений статус має встановлюватися після дії рекрутера.

## Відомий технічний факт
У коді вже є реальний документний менеджер `documents.js`; тому не створювати новий паралельний менеджер на `localStorage`.
