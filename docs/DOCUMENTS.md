# TRORECRUITER — Документи

## Канонічний контур
1. Користувач працює з документом конкретного кандидата.
2. Файл зберігається у Supabase Storage bucket `candidate-documents`.
3. Канонічний запис про документ зберігається в `public.documents`.
4. `candidate_id` зв'язує документ з кандидатом.
5. `requirement_id` зв'язує документ із вимогою комплекту з `document_requirements`.
6. OCR/AI обробляє документ.
7. Рекрутер перевіряє результат.
8. Підтверджений документ відображається як виконана вимога комплекту.

## Підтверджено в коді
`documents.js` уже реалізує основний документний pipeline:
- upload у `candidate-documents`;
- OCR;
- `ai-classify-document`;
- `documents.insert(...)`;
- відображення статусів;
- відкриття файла через signed URL.

## Поточний розрив
Є два шляхи завантаження:
- загальний документний менеджер `documents.js`;
- окремий шлях рекомендаційного листа у `script.js` (`uploadRecommendation`).

Їх треба об'єднати в один канонічний pipeline.

## Виявлена невідповідність типу
У `document_requirements` фактична вимога має назву:
`Копія рекомендаційного листа`

У `script.js` зараз записується:
`Рекомендаційний лист`

Канонічна назва має бути узгоджена з довідником, щоб документ гарантовано відображався у правильному рядку комплекту.

## Виявлена невідповідність MIME
Таблиця `documents` наразі має CHECK, який фактично дозволяє лише `application/pdf`.

Водночас `documents.js` підтримує PDF/JPG/JPEG/PNG/DOC/DOCX.

Це треба виправити до розширення документного контуру.

## Статуси
Поточна модель БД містить окремі поля:
- `status`;
- `processing_status`;
- `verification_status`;
- `checked_at`;
- `checked_by`;
- `verified_at`;
- `verified_by`.

UI вже використовує логіку:
- `Завантажено · перевірити`;
- `AI розпізнано · перевірити`;
- `Підтверджено`.

AI/OCR не повинен автоматично робити документ підтвердженим.

## Правильний життєвий цикл
`Завантажений → Розпізнаний → Перевірений/Підтверджений`

## Важливий принцип
Storage — це фізичний файл.
`public.documents` — канонічний реєстр документа особової справи.
Наявність файла у Storage без запису в `documents` вважається незавершеним завантаженням.
