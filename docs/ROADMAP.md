# TRORECRUITER — Roadmap

## Поточний етап: стабілізація документів
- [x] Supabase інтеграція
- [x] Storage bucket `candidate-documents` використовується кодом
- [x] Таблиця `documents` використовується CRM
- [x] `document_requirements` використовується для комплекту
- [x] OCR/AI класифікація рекомендаційного листа
- [x] Поле `Тип документа`
- [x] Проведено аудит фактичного document pipeline
- [x] Зафіксовано розрив між Storage та `documents`
- [x] Зафіксовано невідповідність `Рекомендаційний лист` ↔ `Копія рекомендаційного листа`
- [x] Зафіксовано невідповідність MIME CHECK у БД та підтримуваних форматів frontend
- [x] Додано repair-guard для реєстрації рекомендаційного листа в `documents` після створення нового кандидата
- [ ] Об'єднати шлях рекомендаційного листа з канонічним `documents.js` pipeline без дублювання
- [ ] Узгодити канонічний `document_type` та `requirement_id`
- [ ] Виправити MIME-обмеження `documents`
- [ ] Перевірити фактичний INSERT у `documents` після створення нового кандидата
- [ ] Перевірити зв'язок `document -> candidate_id`
- [ ] Узгодити `status` / `processing_status` / `verification_status`
- [ ] Перевірити, що підтвердження рекрутером реально записується в БД
- [ ] Перевірити RLS та Storage policies після змін
- [ ] Додати перевірку на сирітські файли Storage
