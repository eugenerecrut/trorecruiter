# Ручна звірка ID та витягів про проживання

Підтверджений рекрутером чинний результат ID може використовуватися для перенесення дозволених порожніх полів навіть за збереженої нульової оцінки AI. Оцінка й первісний результат AI не підвищуються штучно.

Виняток стосується лише оцінки впевненості. Він вимагає того самого кандидата, точних реквізитів джерела, чинного статусу обробки, перевіряльника та дати підтвердження не раніше останньої редакції результату. Перевірки власника, номера, дат, РНОКПП та УНЗР діють завжди. Новий результат провайдера не успадковує підтвердження попереднього результату. Повторне редагування розпізнаних реквізитів вимагає нової звірки.

Планувальник перевіряє однакове джерело як для полів кандидата, так і для паспортних полів профілю. Заповнені ручні значення мають пріоритет; рішення залишити картку записується окремо зі знімком джерела.

Точні назви витягів про зареєстроване місце проживання нормалізуються до одного типу документа. Дати формування витягу й реєстрації не змішуються; витяг не стає паспортним джерелом. Підказка про очікуваний тип не перекласифіковує довільний витяг.

Регресії: `tests/crm-manual-source-review.cjs`, зокрема повний план перенесення полів кандидата й профілю, застаріле підтвердження, інший власник і неприпустимі реквізити.
