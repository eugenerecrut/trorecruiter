# Прив’язка рішення «залишити дані картки» до джерела

Нові рішення зберігає чинна `crm_keep_document_value` з тим самим API. Автор і час встановлюються сервером; перевірки активного працівника, RLS, належності документа, актуальної версії та CAS збережені. Таблиці, політики доступу й значення картки не змінюються.

## Формат

`ai_extracted._crm_review_context` містить `version: 1`, серверний UUID `id` і `source`: ID документа та кандидата, тип, групу/номер версії, шлях, хеш файла, точний JSON розпізнавання без двох кореневих службових ключів `_crm_review_context` і `_crm_review_decisions`.

Кожне нове рішення має `source_binding: {version: 1, context_id}`. Один знімок спільний для всіх рішень документа. Зміна джерела створює новий контекст; історичні рішення залишаються, але не застосовуються до нового контексту. Повторне збереження ідентичного рішення в тому самому контексті не додає дубліката і не виконує UPDATE.

`CRMReviewDecision` у чинному `crm-intake.js` перевіряє знімок, належність кандидату та точне питання. Цим самим matcher користується `candidate-facts.js`. Відсутня/пошкоджена прив’язка нового формату не стає старим погодженням. Порядок ключів JSON-об’єкта не впливає на порівняння, порядок масивів і значення впливають.

## Сумісність і межі

- Старі рішення без `source_binding` зберігають попередню поведінку; діагностика позначає їх `container-only`. Масового переписування або закриття питань немає.
- Це захист від застарілого рішення, а не криптографічний доказ автентичності чи достовірності OCR. Доступ продовжує контролювати Supabase.
- Повторний OCR з ідентичним JSON і незмінними реквізитами джерела не вважається іншими даними. Час `ai_processed_at` не використовується: чинний тригер змінює його також під час збереження рішення.
- Спільний знімок збільшує `ai_extracted` приблизно на розмір одного результату OCR. Він не дублюється для кожного рішення. Чинний журнал може зберігати ці зміни; його обсяг треба враховувати. Викликів AI немає.
- Перевірка SQL використовує ізольований PostgreSQL WASM із синтетичними ролями/RLS. Вона не замінює аудит усіх робочих тригерів; визначення актуальних тригерів перевірено окремо. Тести CAS перевіряють застарілі запити, але не моделюють паралельні мережеві транзакції.

## Розгортання та відкат

Перед заміною функції зберігається її фактичне визначення. Новий клієнт сумісний зі старими рішеннями. Для відкату серверної частини відновити попереднє визначення функції; нові історичні метадані можна залишити. Не повертати старий клієнт, який не перевіряє нову прив’язку, без оцінки вже створених нових рішень.

Тести: `tests/crm-review-source.cjs`, `tests/crm-review-source-sql.cjs`, `tests/crm-candidate-facts.cjs`. SQL runtime зафіксовано lockfile у `tests/sql-runtime`; він використовується тільки тестами, а не CRM.
