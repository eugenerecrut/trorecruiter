# Приймання тіньового групування СПЛАВ

Для контролю потрібна окрема синтетична задача. Новий воркер вимагає її точний ідентифікатор у `SPLAV_REVIEW_SHADOW_JOB_ID`; без нього модель не викликається навіть із ввімкненим прапорцем.

1. У тестовому проєкті розгорнути версію воркера з цього коміту й підготувати синтетичну справу зі щонайменше двома питаннями. При вимкненому прапорці перевірити завершення звірки та відсутність `review_shadow` у відповіді воркера.
2. Встановити `SPLAV_REVIEW_SHADOW=1`, `SPLAV_REVIEW_SHADOW_JOB_ID` (ідентифікатор саме синтетичної задачі), `SPLAV_REVIEW_SHADOW_MODEL` та ключ OpenRouter. Виконати один тестовий прохід і зафіксувати `original_count`, `group_count` та тривалість. Звірити, що кожен початковий індекс зустрічається рівно раз, а різні за змістом питання залишаються окремими.
3. Порівняти збережений звіт із проходом без моделі: статус, вихідні питання й джерела мають збігатися. Пропозиція групування є лише у відповіді воркера; UI її ще не показує.
4. Після контролю вимкнути прапорець. Відсутність прапорця, моделі або ключа вимикає запит. Збій провайдера не змінює збережену звірку і не запускає повтор обробки.
