# Наскрізна перевірка перебудови CRM

Дата: 16.10.2026. Усі персональні дані синтетичні. Робоча база й файли кандидатів не змінювалися.

## Перевірений шлях

Чинна функція пакетного завантаження з documents.js → реєстрація кожного файла → виклик AI за точним ID документа → збереження ai_extracted → справжні модулі нормалізації та синхронізації → повторне читання картки → перевірка готовності → чинний генератор PDF послужного.

Storage, Edge Function та клієнтський RPC у наскрізному сценарії підставлені тестовим сховищем. Відповіді AI задані наперед: цей тест не оцінює якість реального OCR. Сам RPC окремо перевірений на ізольованому PostgreSQL із застосуванням підготовлених міграцій.

## Пакет і результати

- Свідоцтво про народження: місце народження, мати, її дата народження й джерела збережені.
- Диплом без загального full_name: власник перевірений за owner_full_name запису; професійно-технічна освіта збережена.
- Помилка AI одного файла: файл лишився зареєстрованим, наступні файли оброблено.
- Трудова книжка: події прийняття/звільнення зібрано в період роботи.
- РЛ: ВОС заповнено; неправильне ШПК відхилено; мобілізація не замінена контрактом.
- Документ іншої особи: передано на звірку, чужі дані в картку не перенесено.
- Точний повтор файла в одному пакеті: пропущено до повторного завантаження.
- Повторна синхронізація: родичі та факти не дублюються.
- Послужний: 10 сторінок; розміри кожної сторінки рівні вихідному бланку. Освіта, батьки, робота й відсутність служби потрапили у відповідні поля. Сторінки освіти та роботи оглянуті візуально; геометрія шаблона не змінювалася.

## Перевірки

65 автоматизованих тестів, 16 сценаріїв ізольованого PostgreSQL, 37 браузерних перевірок V3. Окремо пройдено браузерний звіт готовності та дашборд: стани документів, пошук, фільтр оформлення, порожній результат, відкриття документів, мобільна ширина. Помилок JavaScript у цих браузерних сценаріях немає.

Додані tests/crm-upload-pipeline.cjs і tests/crm-dashboard-browser.cjs. PDF-частина першого тесту вмикається CRM_PIPELINE_PDF=1; потрібні pdf-lib і fontkit. Шляхи можна задати CRM_NODE_MODULES і CRM_FONTKIT_MODULE. CRM_PIPELINE_PDF_OUTPUT дозволяє зберегти синтетичний PDF для огляду.

## Що ще потрібно перед публікацією

1. Повторно звірити визначення робочого RPC та підготовлені міграції; перевірити резервування.
2. Застосувати міграції й узгоджене оновлення Edge Function та клієнта.
3. Перевірити один погоджений пакет із реальним AI й повторне відкриття картки в робочій CRM.
4. Звірити повний PDF-пакет і фактичний вигляд усіх сторінок реального кандидата.

Масову синхронізацію історичних документів цей етап не запускає. Локальна готовність послужного не є підтвердженням перевірки комплектності робочої особової справи.
