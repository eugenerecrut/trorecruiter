# №232: перевірка пріоритету джерел без запису

`identity-shadow-1` порівнює ПІБ, дату й місце народження. Результат містить рішення, код причини, версію правила й джерела. Пропозиція для порожнього поля не є підтвердженням і не змінює картку.

| Поле | Джерела в порядку пріоритету |
| --- | --- |
| ПІБ | Документ, що посвідчує особу → актовий запис / свідоцтво про народження → автобіографія |
| Дата та місце народження | Документ, що посвідчує особу, й актовий запис / свідоцтво про народження → автобіографія |

Для відповідного джерела перевірений запис має пріоритет над неперевіреним. Якщо допустимі джерела не погоджуються, результат — ручна звірка незалежно від рангу або кількості збігів. Повтори одного `sourceKey` не збільшують кількість незалежних джерел. Чинне значення захищено навіть коли походження невідоме. Архівні версії, чужий або не встановлений власник і невідомий тип джерела не допускаються.

Адаптер для етапу C має постачати перевірені `ownerMatch`, `current`, `verified`, клас джерела і ключ походження (той самий для копій одного оригіналу). Їх не можна приймати за словами моделі. Історичні назви зіставляються тільки за явно перевіреним правилом, відповідною територією та датою документа в інтервалі назви. До прототипу не додано реальних топонімів або джерел.

Етап B: чистий прототип і синтетичні тести. Інтеграція з наявним переглядом за прапорцем, чинним CAS та правилами аудиту належить до окремого етапу C.
