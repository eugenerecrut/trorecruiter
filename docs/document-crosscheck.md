# Зіставлення документів — версія 1.2.0

Без нових таблиць/колонок. Перед CRMDocumentSync.apply клієнт читає доступний через RLS пакет кандидата та блокує перенесення полів із суперечностями. Чинні серверні compare-and-set та ручні значення збережені.

Версії відбираються за version_group_id (або id), version_number та created_at. Окремі документи одного типу зберігаються. Для незалежності джерел використовується file_hash, інакше storage_path. Однаковий файл за різними шляхами без хешу поки не виявляється.

РНОКПП, дата і місце народження — скалярні перевірки. Батьки — relationship/relation та ПІБ за роллю. Освіта — заклад, серія й номер диплома. Робота/служба — точний період, вид, установа й посада. Нечітко прив’язані події не об’єднуються. Зміни прізвища не вирішуються голосуванням. Модуль не прирівнює згенеровані CRM форми до первинних джерел та не навчається на власному результаті.

Джерела показано в автопілоті, з відкриттям через короткострокове Storage-посилання. Перед послужним повторно перевіряється пакет, показуються розбіжності й наявні друковані правки. Правки не видаляються; вихідне значення лишається в моделі поруч із правкою.

Автобіографія доповнює відмінні записи освіти, коли наявний диплом достатньо описаний для розрізнення. Канонічні дипломи не перезаписуються, повторна проєкція не створює дублікати.

Обмеження: клієнтська звірка не транзакційна щодо змін інших документів; обхід клієнта не захищений новим серверним правилом. Семантичні зміни адрес, історія родичів, частково перекриті періоди та різні дати події потребують подальшого спеціалізованого зіставлення. Суперечності не усуваються автоматично; автоматичне самонавчання не додане. Доказовість старих OCR-записів не доповнюється вигаданими цитатами. Масова пересинхронізація не виконувалась.

## 1.2.1 — ймовірні зв’язки періодів
За однакового явно визначеного виду діяльності, установи й посади перевіряються перекриття дат. Часткові дати перетворюються лише на діапазон можливих дат для порівняння, не на нову збережену дату. Різні, але перекриті періоди отримують needs_review; відповідний work_records не переноситься автоматично. Неперекриті призначення, різні посади, різні види служби й повторні читання того самого файла не утворюють такого зв’язку. Відсутній kind не вгадується. Це виявлення можливого зв’язку, не автоматичне злиття та не підтвердження факту. Межі дат не обираються за голосуванням.

## 1.2.50 — значення картки поруч із джерелами
Зональний перегляд показує current для РНОКПП, дати й місця народження та батьків. Для структур освіти/періодів, які модуль не завантажує у current, відсутність значення не видається за порожню картку. HTML екранується. Непевний зональний результат зберігає попередження про якість навіть за схожих географічних формулювань. Нового AI або записів до картки немає.

## 1.2.51 — явні географічні позначення
Порівняння враховує точні позначення «обл», «області», «р-н», «району», «село/с», «місто/м». Закінчення «ської/ська», «ського/ський» зіставляються лише у слові безпосередньо перед «область» або «район». Назви населених пунктів так не змінюються. Жодних словників перейменувань, геокодування чи припущень щодо країни.

Для уточнення повноти потрібен один реально наявний запис джерела або картки, який містить усі явні слова інших варіантів після такого порівняння. З кількох неповних записів адреса не синтезується. Результат лише needs_review; автоматичне перенесення залишається заблокованим, оригінальні значення незмінні.

## 1.2.52 — неповні ПІБ батьків
Лише для матері/батька, уже згрупованих за роллю: точні прізвище й ім’я та сумісне по батькові дозволяють needs_review, якщо один варіант неповний або містить одне прізвище в дужках після основного. Зміна основного прізвища, інше ім’я/по батькові, різні явно вказані прізвища у дужках та ініціали так не зіставляються. Дівоче прізвище не використовується як доказ тотожності різних основних прізвищ.

Різні непорожні дати народження або кілька записів тієї самої батьківської ролі у картці блокують цей висновок і залишають conflict. У джерелах та поточній картці показуються наявні дати; повторна копія файла не є незалежним підтвердженням. Різні дати в одному джерелі не губляться під час дедуплікації.

Це лише пояснення зіставлення, не доповнення ПІБ. Чинний mergeRelatives не змінено; ручні підтвердження, записи та джерела збережені. guard блокує автоматичне перенесення needs_review/conflict.
