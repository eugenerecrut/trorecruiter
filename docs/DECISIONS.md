# TRORECRUITER — Рішення проекту

## 2026-09-30 — Джерела правди
1. GitHub — код.
2. Supabase — дані та файли.
3. `docs/` — архітектура, правила, roadmap та прийняті рішення.
4. Чат — робоче обговорення; завершені рішення переносимо в `docs/`.

## 2026-09-30 — Документи
Використовуємо існуючий Supabase Storage та таблицю `documents`. Не створюємо дублікати через browser `localStorage`.

## 2026-09-30 — Перевірка документів
AI/OCR лише розпізнає та класифікує. Для більшості документів статус `Підтверджено`/`Перевірений` встановлюється після перевірки рекрутером.

## 2026-09-30 — Рекомендаційний лист
Рекомендаційний лист є винятком: він розпізнається без AI-структуризації, а після успішного створення нового кандидата та реєстрації файла в `documents` автоматично отримує:
- `processing_status = Не потребує AI`;
- `verification_status = Підтверджено`.

Це правило стосується саме автоматичного сценарію створення нового кандидата з рекомендаційним листом. Для інших типів документів автоматичне підтвердження не застосовується без окремого рішення.

## 2026-09-30 — Розробка
Не вносити ризикові зміни без перевірки фактичного стану `main`. Спочатку інвентаризація, потім точкова зміна, потім тест на реальному тестовому документі.
